# st-regexpresetguard（正则预设守卫）

SillyTavern 正则预设行为修复扩展（外置扩展，不修改酒馆任何源码）。

> 一句话：切换正则预设，只动全局正则——角色卡与预设文件滴水不进。

## 解决什么问题

SillyTavern（实测 v1.17.x）的「正则预设」功能有一个坑：**切换正则预设时，它不只切换全局正则，还会把"局部正则"（存在角色卡里）和"预设内嵌正则"（存在聊天预设 JSON 里）中所有不在清单里的条目批量写成"关闭"，并立即写进角色卡文件和预设文件。**

由于预设快照按"保存那一刻的角色/聊天预设"记录脚本 ID，只要切换时的上下文不同——换了角色、换了聊天预设、或导入过新正则（导入必换新 UUID）——ID 就全部失配，于是整批被误杀。更糟的是"关闭"状态被永久写进文件，之后无论怎么切换聊天预设，读回来的都是关闭状态。

如果你同时使用 cocktail 扩展：它的 `regex-refresh-optimizer` 模块会在 document 捕获层抢先劫持同样的控件、执行同样的官方同步逻辑——是这套危险写盘行为的另一个实际执行者。

本扩展在 **window 捕获阶段**（事件传播路径上必然先于 document 层和控件层，与扩展加载顺序无关）接管这些控件：切换正则预设时**只同步全局正则**，角色卡与预设文件从此不会被改写。

## 安装

把整个文件夹（含 `manifest.json`）拷贝或克隆到：

```
SillyTavern/public/scripts/extensions/third-party/st-regexpresetguard
```

刷新页面，在「扩展」面板里启用。

> 更新扩展后需要 **Ctrl+F5** 强刷：酒馆加载扩展 JS/CSS 的 URL 不带版本号，浏览器会缓存旧文件。

## 使用

本扩展没有任何界面，装上即生效：

- **正则面板 → Regex Presets**：新建 / 保存 / 切换 / 应用，操作方式与官方完全一致，但只影响全局正则；每次切换 toast 提示「开启 N 条，关闭 N 条」，不会默默失效。
- **未保存提醒**：有手动改动未存入预设时，切换前弹窗询问（保存并切换 / 丢弃并切换）。
- **局部正则与预设内嵌正则**的开/关完全归你手动管理，正则预设切换永远不会碰它们。
- 斜杠命令 `/regex-preset` 走同一拦截逻辑。

## 常见问题

**和 cocktail 冲突吗？**

不冲突，是设计好的接管关系。正则预设切换的两个入口（下拉切换、应用按钮）都被本扩展在 window 层抢先截停，cocktail 的处理函数收不到事件、静默让位；它的其余功能（批量启用/禁用、编辑/移动、允许开关、其他模块）不受任何影响。唯一代价：切换预设后的聊天刷新走官方 `reloadCurrentChat`，绕过 cocktail 的增量刷新优化——聊天文件很大时切换会稍慢一两秒。若停用本扩展，cocktail 的优化器（连同其危险写盘行为）自动恢复。

**手机能用吗？**

能。本扩展没有自绘界面，手机浏览器打开同一个酒馆地址即自动生效，无需安装任何东西（已在 390×844 视口实测）。

**以前被误关的局部/预设内嵌正则怎么恢复？**

切到对应的聊天预设 → 正则面板「预设内嵌正则」区 → 官方的批量全选 + 批量启用，两三下即可。历史被误关的条目不恢复也完全没有影响（只是保持关闭）。

**被删除的正则能找回吗？**

不能。本扩展只防"关闭"，不涉及删除；而酒馆对预设文件没有版本历史，删除即消失。如需防删除，需要另行做文件级快照备份。

## 兼容性

- 以 SillyTavern **v1.17.0** 实测通过；v1.18.0 相关控件 ID 未变，预期可用（升级后建议复验一次）。
- 不依赖 cocktail；有 cocktail 则接管其正则预设优化，没有则拦截官方原生行为。
- 扩展真正加载完成的标志：浏览器控制台出现 `[regex_bak] 已加载：正则预设切换只同步全局正则，不再改写角色卡与预设文件。`
