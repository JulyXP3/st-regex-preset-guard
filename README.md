# st-regex-preset-guard（正则预设守卫）

```
说明:
本插件修复酒馆「正则预设」的切换行为: 只切换全局正则, 绝不触碰
角色卡(局部正则)与聊天预设文件(预设内嵌正则)
外置扩展, 不修改酒馆任何源码, 装上即生效, 删掉即还原
禁止商业化行为
```

作者: JulyXp3

仓库地址: [st-regex-preset-guard](https://github.com/JulyXP3/st-regex-preset-guard)

---

## 解决什么问题

酒馆的「正则预设」（正则面板 → Regex Presets）切换时执行的是**全类型同步**：全局正则、局部正则（存在角色卡里）、预设内嵌正则（存在聊天预设 JSON 里）三类一起动——**凡不在预设快照里的条目，一律写成"关闭"，并立即写盘**：局部正则写进角色卡文件，预设内嵌正则写进聊天预设文件。

由于快照按"保存那一刻的角色/聊天预设"记录脚本 ID，只要切换时的上下文不同——换了角色、换了聊天预设、或导入过新正则（导入必换新 UUID）——ID 就全部失配，于是整批被误杀。更糟的是"关闭"状态被永久写进文件，之后无论怎么切换聊天预设，读回来的都是关闭状态。这就是"局部正则/预设正则莫名消失"的根源。

如果你同时使用 cocktail 扩展：它的 `regex-refresh-optimizer` 模块会在 document 捕获层抢先劫持同样的控件、执行同样的官方同步逻辑——是这套危险写盘行为的另一个实际执行者。

本插件在 **window 捕获阶段**接管这些控件：切换正则预设时**只同步全局正则**，角色卡与预设文件从此不会被改写。

## 安装

1. 酒馆 → 扩展 → **安装扩展** → 粘贴本仓库地址：

   ```
   https://github.com/JulyXP3/st-regex-preset-guard
   ```

2. F5 刷新页面（新扩展目录无需重启 Node 服务）。

装好后扩展列表里会多一项 **st-regex-preset-guard**，默认启用；关掉它就等于没装（官方/cocktail 的原行为会回来）。

**更新插件后必须 Ctrl+F5 硬刷新**：酒馆加载扩展 JS 的 URL 不带版本号，浏览器会缓存旧文件。

## 使用

本插件没有任何界面，装上即生效：

- **正则面板 → Regex Presets**：新建 / 保存 / 切换 / 应用，操作方式与官方完全一致，但只影响全局正则；每次切换 toast 提示「开启 N 条，关闭 N 条」，不会默默失效。
- **未保存提醒**：有手动改动未存入预设时，切换前弹窗询问（保存并切换 / 丢弃并切换）。
- **局部正则与预设内嵌正则**的开/关完全归你手动管理，正则预设切换永远不会碰它们。
- 斜杠命令 `/regex-preset` 走同一拦截逻辑。

## 原理

官方把监听器挂在控件元素上（document → 控件的 target 阶段），cocktail 的优化器挂在 document 捕获阶段，两者都比"更早一层"晚。本插件把监听器挂在 **window 捕获阶段**——事件传播路径上 window 必然先于 document 和控件本体（与注册顺序无关）——截停事件后执行自己的"仅全局严格同步"：按预设快照翻转全局正则的 `disabled`，只写 settings.json，绝不调用写角色卡的 `/api/characters/merge-attributes` 和写预设文件的 `/api/presets/save`。

## 测试方法

### 自检

刷新页面，F12 → Console 应看到：

```
[st-regex-preset-guard] 已加载：正则预设切换只同步全局正则，不再改写角色卡与预设文件。
```

### 核心用例：切换正则预设

F12 → Network 面板，切换任意正则预设，期望：

- toast 显示「正则预设「X」已应用：开启 N 条，关闭 N 条」，数字与实际翻转一致
- 网络里只出现 `POST /api/settings/save`（以及切聊天重载的正常流量）
- **不出现** `POST /api/presets/save` 与 `POST /api/characters/merge-attributes` —— 这是判据核心

### 反向对照

扩展面板里关掉本插件 → F5 → 再切换正则预设：`presets/save`（有 cocktail 时它还会顺带写角色卡）会重新出现——那就是官方/cocktail 的原始行为。

### 常见误判

| 现象 | 说明 |
| --- | --- |
| 网络里有 `/api/chats/get`、`/api/characters/get` 等请求 | 切换后重载聊天的正常流量，不是危险写盘 |
| 日志里没看到 `[st-regex-preset-guard]` | 浏览器缓存旧文件；Ctrl+F5 硬刷新 |
| 切换后某预设内嵌正则仍是关闭 | 那是它文件里的状态，本插件从不碰它；想启用就切到该预设手动开 |

## 常见问题

**和 cocktail 冲突吗？**

不冲突，是设计好的接管关系。正则预设切换的两个入口（下拉切换、应用按钮）都被本插件在 window 层抢先截停，cocktail 的处理函数收不到事件、静默让位；它的其余功能（批量启用/禁用、编辑/移动、允许开关、其他模块）不受任何影响。唯一代价：切换预设后的聊天刷新走官方 `reloadCurrentChat`，绕过 cocktail 的增量刷新优化——聊天文件很大时切换会稍慢一两秒。若停用本插件，cocktail 的优化器（连同其危险写盘行为）自动恢复。

**手机能用吗？**

能。本插件没有自绘界面，手机浏览器打开同一个酒馆地址即自动生效，无需安装任何东西（已在 390×844 视口实测）。

**以前被误关的局部/预设内嵌正则怎么恢复？**

切到对应的聊天预设 → 正则面板「预设内嵌正则」区 → 官方的批量全选 + 批量启用，两三下即可。历史被误关的条目不恢复也完全没有影响（只是保持关闭）。

**被删除的正则能找回吗？**

不能。本插件只防"关闭"，不涉及删除；而酒馆对预设文件没有版本历史，删除即消失。如需防删除，需要另行做文件级快照备份。

## 兼容性

- 以 SillyTavern **v1.17.0** 实测通过（含手机视口）；v1.18.0 相关控件 ID 未变，预期可用（升级后建议复验一次）。
- 不依赖 cocktail；有 cocktail 则接管其正则预设优化，没有则拦截官方原生行为。
